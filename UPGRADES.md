# Deployment

The deployable consists of the `curriculum` CLI, the `curriculum-nexus`
service, the `roles.datom` file, the consumer workspace, and the three authored
skill repositories. Set `CURRICULUM_PSYCHES_REPOSITORY_DIR` to the Psyche
repository root. Set `CURRICULUM_MIND_SKILLS_DIR` and
`CURRICULUM_FIELD_SKILLS_DIR` to the Mind and Field `skills/` directories. Set
`CURRICULUM_ROLES_FILE` to `roles.datom`, `CURRICULUM_WORKSPACE` to the
consumer workspace, and `XDG_RUNTIME_DIR` to the runtime root containing
`curriculum/curriculum.sock`.

Build the CLI with the `datom` feature. The Nexus binary uses typed archived
signals and does not need Datom. Send `RebuildSkills` when the workspace needs
its current skill and role projections. Use path-only `EditSkills` signals for
source changes within the currently configured roots. `CheckSkills` rereads
the authored roots and checks every generated skill tree and role packet
without writing.

Changing a configured repository root is a service configuration change, not
a path edit. Restart the Nexus after changing the root; `SkillMemory::open`
loads the registry from the configured roots. Then send `RebuildSkills` to
project that registry and role data. Do not send `EditSkills` paths from the
previous root after switching roots.

# Upgrade 0.1.0 to 0.2.0: the 0.33 codec cohort and scalar newtypes

Source only; nothing is deployed or refurnished by this revision. It is built on 478c (0380 plus the
dual Layer or Model caller acceptance) and keeps `roles.datom`, `curriculum.ethos` and every
variant of `Outcome` and `Query` as they are.

**Pins.** datom-codec 0.33.0 (`eabe`), protos 0.33.0 (`3c7a`) and, as a dev dependency, ethos-zero
19.2.0 (`5a5d`). `src/generated.rs` is regenerated by that generator from the unchanged
`curriculum.ethos`; `tests/generated_equality.rs` regenerates it in the test run and compares byte
for byte.

**Wire and text.** The wire is unchanged for the values tested: `tests/wire_equality.rs` builds the
same data in the 478c types, taken verbatim from `src/generated.rs` at 478c as
`tests/support/previous_478c.rs`, and in the current types, and the rkyv archives are byte equal for
every `Query`, `CliRequest` and `Outcome` variant (`Rejected(String)` stays the fifth), a
`RolesDocument` and a `ProjectionCandidate`; with `datom` the text is equal too, and an old archive
restores as the current value. A running Flow 0.53.1 that speaks the 0.1.0 wire therefore reads and
writes the same bytes for those values. These are representative values, not all values.

**Source API.** The 32 scalar type aliases of `generated.rs` are newtype structs: `ModuleIdentity`,
`RepositoryName`, `SourceRevision`, `SourceRoot`, `SourceRelativePath`, `ModuleType`,
`ModuleSubject`, `DeclaredPlacement`, `SourceSha256`, `BodySha256`, `RenderedSha256`,
`SystemModules`, `UserModules`, `FlowId`, `SystemText`, `UserText`, `RecordsText`,
`SystemPayloadSha256`, `UserPayloadSha256`, `RecordsPayloadSha256`, `DeploymentDestination`,
`PublishedInventoryDigest`, `PublishedContentDigest`, `RendererVersion`, `RoleName`, `ModelId`,
`DescriptionModule`, `ContextModules`, `DescriptionText`, `ContextText`,
`DescriptionPayloadSha256` and `ContextPayloadSha256`. A caller wraps where it built a string, as
`ModuleIdentity("spirit:core".into())`, and reads the scalar from `.0`. Inside Curriculum the registry
keeps plain strings and wraps and unwraps at the generated-type boundary. The `ReaderBudget` of
protos 0.33.0 is built with `try_from`.

**Checks.** The repository now has a `flake.nix` with the package recipe Primary builds and two
checks: `test`, the whole suite with the `datom` feature, and `test-default`, the default features.

**Deploy.** Primary's `curriculum` package pins Curriculum and its git dependencies by hash; it needs
the new `outputHashes` for datom-codec 0.33.0, protos 0.33.0 and ethos-zero 19.2.0, which are in this
revision's `flake.nix`.
